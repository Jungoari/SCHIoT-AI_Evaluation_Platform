# 정원에게 확인할 것 · 운영진 질의 목록

> 개발을 멈추지 않기 위해 아래 항목은 **합리적인 기본값으로 먼저 구현**해 두었다. 답에 따라 설정만 바꾸면 된다.

## A. 정원이 결정할 것

| # | 질문 | 현재 구현 (기본값) | 바꾸려면 |
|---|---|---|---|
| A1 | 라이브 데모를 어디에 배포할까? (비용 발생 OK 확인함) | 미배포. 로컬 `docker compose up` 으로 완전 동작 | Docker 가 되는 VM 필요 (샌드박스 때문에 일반 PaaS 불가). 후보: AWS Lightsail / Oracle Cloud / 학교 서버 |
| A2 | 팀원 있음? (일정·발표 분담) | 1인 기준 | — |
| A3 | 지금까지 작업을 커밋할까? | 커밋 안 함 (첫 커밋 이후 변경 전부 미커밋) | 승인하면 기능 단위로 나눠 커밋 |
| A4 | GitHub 저장소 이름·공개 여부 | 미생성 | `gh` CLI 설치 또는 GitHub 웹에서 생성 |
| A5 | 데모 대회 이름·과제 구성 그대로 괜찮은가 | "2026-2 머신러닝 기말 프로젝트" (손글씨 숫자 분류 / 당뇨 진행도 회귀) | `web/apps/core/demo.py` |

## B. 운영진(오픈채팅)에 물어볼 것 — RFP 해석이 갈리는 부분

| # | 질문 | 우리 해석 (구현됨) | 근거 |
|---|---|---|---|
| B1 | 관리자1 계정은 어떻게 만드나? | 대회마다 **운영(관리자1) 전용 참여 코드**를 따로 발급 | RFP p.3 "참여자, 관리자1: 회원가입 (코드 필수)" — 역할 구분 방법 미기재 |
| B2 | 리더보드는 프로젝트 단위인가, 마감일 단위인가? | **프로젝트 단위** (모든 마감 구간 통틀어 최고 점수). 횟수만 마감일별 | RFP p.6 "참여자별 최고 CSV 점수 하나" |
| B3 | 업로드 시작 후 완료까지 허용 시간 기준이 있나? | 프로젝트별 설정, 기본 **30분** | RFP p.4 시간 기준 미기재 |
| B4 | 평가 때 실제 실행해 보나, README·발표·영상만 보나? | 둘 다 대비: 명령 1줄 실행 + GIF·영상 | — |
| B5 | 실제로 쓸 평가 지표 목록이 있나? | 분류 4종(Accuracy, Macro/Weighted F1, Balanced Acc), 회귀 3종(RMSE, MAE, R²) | 지표는 한 줄로 추가 가능 (`grading/metrics.py`) |
| B6 | GPU 모델(PyTorch·TF) 재실행 검증도 필요한가? | CPU sklearn 기본, 샌드박스 이미지에 패키지 추가로 확장 | RFP p.4 "scikit-learn, PyTorch, TensorFlow 파라미터 파일" |
| B7 | 마감일 변경 시 이미 집계된 제출의 소속 구간을 다시 계산해야 하나? | 제출 시점에 소속 구간을 고정 (변경 이력은 감사 로그) | 공정성·재현성 |
| B8 | 관리자2가 관리자1 제안 없이 바로 확정해도 되나? | 관리자2도 '제안'을 거친 뒤 확정 (자기 승인은 경고·기록) | RFP p.6 흐름도 |

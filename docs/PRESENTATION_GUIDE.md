## 2. 요구사항 슬라이드의 표준 구도 (좌: 요구사항 패널 / 우: 시각 자료)

```
┌───────────────────────────────────────────────── [SCH] ┐
│  R-18 마감 규칙                                          │ ← 제목: 요구사항 번호 + 이름
├────────────────────────┬────────────────────────────────┤
│ ① RFP 요구사항   p.4   │                                │
│ ·마감 전 시작·마감 후   │                                │
│  완료 시 채점          │                                │
│ ·마감 후 제출은 접수만  │      GIF / 다이어그램 / 표       │
├────────────────────────┤      (테스트 시연 화면)          │
│ ② 왜 중요한가          │                                │
│ ·대용량 가중치 업로드   │                                │
│  지연으로 인한 불이익   │                                │
├────────────────────────┤                                │
│ ③ 어떻게 해결했나       │  ✅ TC-B01 PASS · TC-B03 PASS   │ ← 캡션: 관련 TC 결과
│ ·서버 시각 업로드 티켓  │                                │
│ ·해시 선언으로 바꿔치기 │                                │
│  차단                  │                                │
└────────────────────────┴────────────────────────────────┘
       좌측 약 3.7in              우측 약 5.0in
```

**좌측 패널 규칙**
- 세 칸 고정: **① RFP 요구사항 ② 왜 중요한가 ③ 어떻게 해결했나** (모든 요구사항 슬라이드에서 같은 위치·같은 순서 → 심사위원이 금방 익숙해짐)
- 각 칸은 연한 남색 배경 카드로 구분하고, 칸 제목 옆에 작은 아이콘(문서·느낌표·방패 등) 배치
- 칸마다 2~3줄, 14pt 이상. 넘치면 문장을 줄인다 (글자 크기는 줄이지 않는다)
- ① 칸 우측 상단에 RFP 쪽 번호 표기 (예: `p.4`) → 근거를 바로 확인 가능
- ③ 칸에서 **우리가 추가로 발견한 문제**를 해결한 부분은 강조 색으로 표시

**우측 시각 자료 규칙**
- 우선순위: 테스트 시연 GIF > 흐름 다이어그램 > 표
- 하단 캡션에 관련 TC 결과 표시 (예: `✅ TC-B01 PASS`)
- PowerPoint는 GIF 애니메이션을 재생하므로 GIF를 그대로 삽입. PDF로 내보낼 때를 대비해 대표 프레임 이미지도 준비

## 4. 좌측 패널 초안 (개조식, 마침표 없음)

### 6. 정답 보호 `p.2, p.5, p.7`
- **① 요구사항**: 참여자에게 정답 비노출 / 참여자 코드 실행 시 정답·비밀키·타인 자료·관리 기능 접근 차단
- **② 왜 중요한가**: 정답 유출 시 대회 전체 무효 / 되돌릴 수 없는 유일한 사고
- **③ 해결**: 정답 보유 프로세스와 코드 실행 프로세스 물리적 분리 / 네트워크 차단·읽기 전용 샌드박스 / 훔칠 정답이 없는 실행 환경

### 7. 계정·참여 코드 `p.3`
- **①**: 대회 개설 시 코드 자동 생성 / 최초 가입 시 코드 필수 / 기존 회원은 코드로 대회 추가
- **②**: 대회에 속하지 않은 계정 방지 / 학생 1명 = 계정 1개로 여러 과목 참여
- **③**: 역할별 코드(참여자·운영) 발급 / 코드 만료·재발급 / 코드 입력 실패 횟수 제한

### 8. 마감 규칙 `p.4`
- **①**: 마감 전 시작·마감 후 완료 시 채점 / 마감 후 제출은 접수만
- **②**: 대용량 업로드 지연으로 인한 불이익 방지 / 규칙 악용 시 공정성 훼손
- **③**: 서버 시각 기준 업로드 티켓 / 시작 시 파일 해시 선언으로 바꿔치기 차단 / 유예 시간 제한

### 9. 제출 횟수 `p.5`
- **①**: 마감일별 횟수 제한 / 성공 1회 차감 / 형식·시스템 오류 미차감 / 부적합 차감 유지
- **②**: 반복 제출로 정답을 역추적하는 리더보드 프로빙 방지 / 학생 책임 없는 오류로 인한 손해 방지
- **③**: 좌석 예약 방식 차감 / DB 행 잠금으로 동시 제출 경쟁 조건 차단 / 시스템 오류 자동 재시도

### 10. CSV 형식 검사 `p.4~5`
- **①**: 관리자2 등록 형식 기준 자동 검사 / 레이블·행·열 수 확인
- **②**: 잘못된 파일로 인한 채점 오류 방지 / 학생이 오류 원인을 모르는 답답함 해소
- **③**: 정답 CSV로 규격 자동 추론 / 브라우저 사전 검사 + 서버 재검사 / 행 단위 구체적 오류 일괄 안내

### 11. 리더보드 `p.6`
- **①**: 참여자별 최고 점수 1개 / 미검증 포함 + 상태 표시 / 동점 공동 순위 / 참여자 익명·관리자 실명
- **②**: 경쟁을 통한 동기 부여 / 성적은 개인정보 / 미확정 점수로 인한 분쟁 방지
- **③**: 무작위 익명 별칭 / 서버에서 역할별 화면 생성 (실명 미전송) / 표시 자릿수 기준 동점 비교

### 12. 2단계 검증 `p.6`
- **①**: 최고 점수부터 검토, 동점은 최신부터 / 관리자1 제안만으로 제외 불가 / 관리자2 승인으로 확정
- **②**: 1인 판단의 실수·편파 방지 / 학생당 수십 건의 제출을 모두 검토하는 부담 해소
- **③**: 상태 머신으로 전환 순서 강제 / 부적합 승인 시 다음 기록 자동 상정 / 모든 판정 감사 로그 기록

### 13. 부정 제출 판별 `p.8 ★`
- **①**: CSV가 모델 추론 결과인지, 우회 수행인지 판단하는 프로세스
- **②**: 조교 업무 중 가장 오래 걸리고 놓치기 쉬운 작업 / 공정성과 직결
- **③**: 무결성 리포트 신호등 / 오답 일치율로 복사 탐지 / 검토 대상만 추론 재실행 / 최종 판단은 사람

### 14. 노트북·파일 보안 `p.7`
- **①**: 파일 내용 검증·안전한 저장명 / 노트북 비신뢰 HTML·스크립트·위젯 안전 처리
- **②**: 위장 파일·경로 조작 공격 / 노트북 열람 시 관리자 계정 탈취 위험
- **③**: 매직 바이트·파싱 검증 / UUID 저장명 / 스크립트 제거 + 격리 iframe + CSP 3중 방어 / 가중치 pickle은 샌드박스에서만 로드

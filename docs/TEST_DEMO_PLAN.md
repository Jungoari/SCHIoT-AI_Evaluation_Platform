## 1. 왜 테스트 케이스를 GIF로 보여주나 (명분)

| 평가 항목 | 효과 |
|---|---|
| 필수 기능 (40) | RFP의 규칙(마감 경계, 차감 규칙, 동점 등)이 **말이 아니라 동작으로** 확인된다 |
| 설계·보안 (20) | 보안 공격을 실제로 시도하고 막히는 장면은 보안 설계에 대한 가장 강력한 증거다 |
| 창의 (20) | "GIF가 곧 테스트"라는 방식 자체가 차별점이다. UI를 수정해도 명령 한 번으로 모든 증거를 다시 만든다 |

## 2. GIF 화면 구성 (공통 포맷)

```
┌──────────────────────────────────────────────────────────┐
│ TC-C04  남은 1회에서 동시 제출 10건            [SECURITY] │ ← 상단 캡션 바 (TC 번호, 시나리오, 분류)
│ 기대 결과: 정확히 1건만 채점, 9건은 "횟수 초과"            │
├──────────────────────────────────────────────────────────┤
│                                                          │
│                   실제 앱 화면 (녹화)                      │
│              클릭 위치는 원형 하이라이트                    │
│                                                          │
├──────────────────────────────────────────────────────────┤
│ ✅ PASS  채점 1건 · 거부 9건 · 남은 횟수 0                 │ ← 테스트 단언이 통과하면 표시
└──────────────────────────────────────────────────────────┘
```

- 규격: 1280×720 녹화 → 960px GIF, 15fps, 장당 10~25초, 5MB 이하
- 캡션·PASS 표시는 테스트 코드가 페이지에 오버레이를 주입하는 방식 (앱 코드에는 포함하지 않음, 데모 모드에서만 동작)
- 여러 역할을 비교하는 GIF는 **화면 분할**(왼쪽 참여자 / 오른쪽 관리자)
- 색: PASS 초록, 차단된 공격은 "🛡️ BLOCKED" 빨강 → 초록 (막힘 = 성공)

## 5. 제작 방법

```
scripts/record_gifs/
├── conftest.py          # 데모 데이터 초기화, 비디오 녹화 설정
├── overlay.js           # 캡션 바 · 클릭 하이라이트 · PASS 도장 주입
├── test_g03_submit.py   # GIF 1개 = Playwright 테스트 1개
├── ...
└── make_gifs.sh         # 녹화 실행 → ffmpeg 자르기 → gifski 변환 → docs/assets/gifs/
```

1. `seed_demo.py`로 매번 같은 데모 상태를 만든다 (같은 학생, 같은 점수 → GIF 일관성)
2. Playwright가 브라우저를 조작하고 녹화한다 (`record_video`)
3. 각 단계에서 `overlay.js`가 캡션을 갱신하고, 테스트 단언이 통과하면 PASS 도장을 찍는다
4. 마감 경계(B01)는 마감 시각을 "지금 + 15초"로 시드하고 업로드 속도를 제한해 재현한다 → 실제 시간 흐름 그대로
5. 시스템 오류(C03)는 테스트가 워커 컨테이너를 강제로 종료해 재현한다
6. `make_gifs.sh` 한 번 실행으로 17개 GIF를 모두 다시 만든다

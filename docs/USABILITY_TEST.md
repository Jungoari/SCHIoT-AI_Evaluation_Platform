# 사용성 테스트 · 업무 시간 실측 진행 가이드

> 목적: "쓰기 편하다", "업무 시간이 줄었다"는 주장을 **사람이 직접 써 본 숫자**로 증명 (평가 항목: 사용성과 업무 효율 20점)
> 소요: 테스터 1명당 약 20분 · 업무 시간 실측 약 30분
> 결과 정리: `scripts/usability_report.py` 가 README 에 붙일 표를 만들어 준다

---

## 1. 준비 (진행자, 5분)

```bash
docker compose up -d                                              # 또는 로컬 runserver
docker compose exec web python manage.py usability_kit --out /data/usability_kit
docker compose cp web:/data/usability_kit ./var/usability_kit     # 내 PC 로 복사
```

로컬 개발 서버라면 `cd web && ../.venv/bin/python manage.py usability_kit` (결과: `var/usability_kit/`)

만들어지는 것

| 파일 | 용도 |
|---|---|
| `README.txt` | **진행자 전용** — 새 참여 코드, 관리자 계정 (테스터에게 보여주지 않기) |
| `solution.ipynb`, `model.joblib` | 테스터가 제출할 노트북·가중치 |
| `submission_wrong.csv` | 과제 2: 처음 낼 CSV (정답 열 이름을 일부러 `digit` 으로 틀림) |
| `submission.csv` | 과제 2: 오류 안내를 보고 고쳐 낼 CSV |

> 참여 코드를 새로 발급하면 기존 참여자 코드는 무효가 된다. 테스트가 끝나면 관리자2 화면에서 다시 재발급
> 테스트가 끝난 뒤 테스터 계정은 **삭제가 아니라 '회원 관리 → 비활성화'** 로 정리한다 (감사 로그가 계정을 참조하므로 삭제되지 않게 설계됨). 데모를 처음 상태로 되돌리려면 `python manage.py seed_demo`
> 참여 코드는 소문자·하이픈 없이 입력해도 인식된다 (파일럿 확인) — 테스터가 코드 형식 때문에 막히지 않음

준비물: 기록용 `docs/usability/*_template.csv` 3개를 복사 (`_template` 을 뺀 이름으로), 스톱워치

## 2. 진행 규칙

- 테스터: 학과 동기 **3~5명** (5명이면 사용성 문제의 약 85% 발견 — Nielsen)
- **도와주지 않는다.** "어디를 눌러야 해?"라고 물으면 "어떻게 하실 것 같아요?"로 되묻기
- 생각을 소리 내어 말하게 한다 (Think-aloud) → 머뭇거린 곳·잘못 누른 곳을 `note` 에 기록
- 시간은 과제 문장을 다 읽은 순간부터, 목표 화면에 도달한 순간까지
- `errors` = 잘못된 메뉴 클릭, 되돌아가기, 같은 오류 반복 횟수
- 5분 안에 못 하면 중단하고 `completed=N`

## 3. 과제 (테스터에게 그대로 읽어 주기)

| # | 과제 문장 | 성공 기준 |
|---|---|---|
| 1 | "받은 참여 코드로 회원가입하고, 손글씨 숫자 분류 프로젝트에 파일 3개(`submission_wrong.csv`, 노트북, 가중치)를 제출해 주세요" | 제출 화면에서 결과(오류)가 표시됨 |
| 2 | "방금 제출이 왜 실패했는지 확인하고, 고친 파일(`submission.csv`)로 다시 제출해 주세요. 제출 횟수가 줄었는지도 알려 주세요" | 점수가 표시되고, "형식 오류는 횟수 미차감"을 테스터가 말함 |
| 3 | "지금 내 순위와 1등과의 점수 차이를 알려 주세요" | 리더보드에서 내 행을 찾아 말함 |
| 4 | (조교 역할, `ta@demo.evalhub`) "검토할 제출 중 부정이 의심되는 것을 하나 찾아 '부적합' 판정을 제안해 주세요" | 🔴 제출에 부적합 제안 완료 |

과제 4는 관리자 화면 사용성 확인용. 시간이 부족하면 테스터 중 2명만 진행

## 4. SUS 설문 (과제 직후, 2분)

각 문항에 **1점(전혀 아니다) ~ 5점(매우 그렇다)** 으로 답한다. 생각하지 말고 바로 답하게 한다

| # | 문항 |
|---|---|
| 1 | 이 시스템을 자주 사용하고 싶다 |
| 2 | 이 시스템은 불필요하게 복잡하다 |
| 3 | 이 시스템은 사용하기 쉽다 |
| 4 | 이 시스템을 쓰려면 기술적인 도움이 필요할 것 같다 |
| 5 | 이 시스템의 여러 기능이 잘 통합되어 있다 |
| 6 | 이 시스템은 일관성이 없는 부분이 너무 많다 |
| 7 | 대부분의 사람들이 이 시스템을 금방 익힐 것 같다 |
| 8 | 이 시스템은 사용하기 번거롭다 |
| 9 | 이 시스템을 사용하면서 자신감이 있었다 |
| 10 | 이 시스템을 쓰기 전에 많은 것을 배워야 했다 |

> 홀수 문항은 긍정, 짝수 문항은 부정 문장이다 (대충 답하는 것을 막기 위한 표준 구성). 점수 계산은 스크립트가 한다
> 구글 폼으로 받아도 된다 — `tester, q1~q10` 열로 내보내면 그대로 쓸 수 있다

마지막으로 한 가지만 묻기: **"가장 헷갈렸던 곳 한 군데는?"** → `note` 에 기록

## 5. 업무 시간 실측 (조교 또는 진행자 본인, 30분)

같은 업무를 **수작업**과 **시스템**으로 각각 해 보고 시간을 잰다. 건수는 작게, 결과는 비율로 말한다

| 업무 | 수작업 방법 | 시스템 방법 |
|---|---|---|
| CSV 채점·점수 기록 (10건) | 엑셀에서 정답과 비교해 정확도 계산 → 성적표에 입력 | 제출 즉시 자동 (대기 시간만 측정) |
| 형식 오류 확인·안내 (5건) | 파일을 열어 열 이름·행 수 확인 → 학생에게 메시지 | 업로드 시 자동 안내 (0초) |
| 순위표 작성 (10명) | 점수 정렬 → 동점 처리 → 공지 | 리더보드 (0초) |
| 부정 의심 1차 선별 (노트북 10개) | 노트북을 하나씩 열어 코드 확인 | 검토 큐의 신호등 확인 → 🔴🟡만 열람 |

`time_log.csv` 에 초 단위로 기록 (`manual_seconds`, `system_seconds`)

## 6. 결과 정리 (5분)

```bash
python scripts/usability_report.py docs/usability/sus_responses.csv docs/usability/task_log.csv docs/usability/time_log.csv
```

출력된 표를 README 의 "사용성 검증" 절과 `docs/PERFORMANCE.md` 3장(추정치 → 실측치)에 붙인다

**발견한 문제는 반드시 고치고 "수정 전 → 후"를 남긴다** — 평가자는 점수 자체보다 *테스트로 찾은 문제를 고쳤다는 사실*을 더 높게 본다

| 발견한 문제 | 테스터 수 | 수정 내용 | 커밋 |
|---|---:|---|---|
| (예) 오류 안내를 못 보고 지나침 | 2/5 | 오류 카드를 화면 위쪽으로 이동·스크롤 | |
